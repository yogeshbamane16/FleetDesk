# Architecture

FleetDesk uses a monorepo structure with a strict separation of concerns between the frontend rendering layer and the backend business API layer.

## Monorepo Layout
- `apps/web`: Next.js App Router (React, TypeScript, Tailwind, shadcn/ui, TanStack Query)
- `apps/api`: FastAPI (Python, SQLAlchemy, Pydantic, Alembic)
- `docs/`: Project documentation
- `.github/workflows/`: CI/CD pipelines

## Frontend (Next.js)
- **Role**: Rendering, UI interactions, authentication UI, routing.
- **State Management**: TanStack Query for server state. React Hook Form + Zod for local form state and validation.
- **Styling**: Tailwind CSS customized for the "Precision in motion" theme.

## Backend (FastAPI)
- **Role**: Business logic, authorization, database mutations, robust API endpoints.
- **ORM**: SQLAlchemy 2.x for database interactions.
- **Migrations**: Alembic.
- **API Contract**: OpenAPI generated by FastAPI.

## Data Layer (Supabase PostgreSQL)
- **Authentication**: Supabase Auth (JWT).
- **Storage**: Supabase Storage for private delivery documents.
- **Tenant Isolation**: Handled via RLS (Row Level Security) and organization_id in tables, verified transaction-locally in FastAPI.
